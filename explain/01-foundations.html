Introduction to Generative AI for Software Testing

1.1.1 (K1) The AI spectrum — the four types

TypeDefinitionTest example
Symbolic AIRule-based system using symbols + logical rules to mimic human decisions.Hand-coded decision rules.
Classical machine learningData-driven; needs data prep, manual feature selection, model training.Defect categorization, predicting problem areas.
Deep learningNeural networks that automatically learn features (no manual feature selection).Finding patterns in images/audio/text.
Generative AIUses deep learning to create new content (text, images, code) by mimicking training patterns.LLMs writing test cases/scripts.
🔑 Key advantage of GenAI for testing: pre-trained models apply directly to test tasks — no extra training phase needed (but it carries risks, see Ch 3).

1.1.2 (K2) Basics of GenAI & LLMs

  • LLM = GenAI model pre-trained on huge text datasets, based on the generative pre-trained transformer.
  • SLM (Small Language Model) = fewer parameters; lightweight, focused, less resource-intensive.
  • Tokenization = breaking text into tokens (char / sub-word / word) — the building blocks the model reads. (Don’t confuse with embeddings.)
  • Embeddings = numerical vector representations of tokens encoding semantic meaning; similar meanings sit close in vector space → retains context & coherence.
  • Transformer = the neural-network architecture; during inference it predicts the next token. Output is statistically plausible — but plausible ≠ correct.
  • Non-deterministic behavior = same input can give different outputs, due to probabilistic inference + hyper-parameters.
  • Context window = preceding text (in tokens) the model can consider at once. Bigger = better long-passage coherence but more compute; exceeding it → model discards earlier info.

1.1.3 (K2) Foundation vs. Instruction-tuned vs. Reasoning LLMs

ModelWhat it isStrength
FoundationGeneral-purpose, trained on vast diverse data.Flexible, but usually needs further adaptation.
Instruction-tunedFoundation model fine-tuned on prompt→response pairs.Follows instructions / formats well (e.g., Gherkin). Aka “non-reasoning”.
ReasoningAdds structured cognition: logical inference, multi-step, chain-of-thought.High-cognitive-load tasks (effort estimation, prioritization with dependencies).

For testing, both instruction-tuned and reasoning LLMs are used — choice depends on task complexity.

1.1.4 (K2) Multimodal LLMs & Vision-Language Models (VLMs)

  • Multimodal LLM = processes multiple modalities (text, image, sound, video); images → embeddings via VLMs.
  • VLM = a subset of multimodal LLMs integrating visual + textual info (captioning, visual Q&A, text-vs-image consistency).
  • In testing: analyze screenshots / GUI wireframes against textual descriptions (defect reports, user stories) → spot visual discrepancies, generate richer cases → more coverage.
⚠️ Remember the direction: VLM ⊂ Multimodal LLM (not the reverse, not interchangeable).

1.2.1 (K2) Key LLM capabilities for test tasks

  • Requirements analysis & improvement — flag ambiguities, inconsistencies, missing info; raise clarifying questions.
  • Test case creation support — suggest cases & objectives from requirements/user stories.
  • Test oracle generation — produce expected results.
  • Test data generation — datasets, boundary values, combinations.
  • Test automation support — generate/improve scripts, suggest techniques.
  • Test result analysis — summaries; classify anomalies by severity/priority.
  • Testware creation — test plans, test/defect reports, kept updated.
❌ Not LLM capabilities: executing all scripts unattended, doing exploratory testing (human, intuitive), generating deployable application code.
