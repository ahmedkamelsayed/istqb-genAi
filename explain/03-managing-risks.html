Managing Risks of Generative AI in Software Testing

≈160 minutes · includes the 2-pt K3 LO 3.1.2

3.1.1 (K1) The three core defects — know these cold

DefectDefinitionTest-task example
HallucinationOutput that is factually incorrect or irrelevant to the task.Inventing fictitious cases, non-existent acceptance criteria, broken scripts.
Reasoning errorMisinterpreting logical structures (cause-effect, conditional, multi-step). LLMs pattern-match, not truly reason.Wrong conclusions in planning / prioritization / math.
BiasOutput favoring certain info/perspectives, from skewed training data.English-only perspectives; skewed synthetic data or criteria.
All three stem from the training data + transformer limitations. Non-determinism makes them hard to “fix” — they can reappear in another conversation.

3.1.2 (K3) Identifying them in LLM output

Hallucination detection: cross-verification (vs docs/requirements/known behavior) · domain-expert consultation · consistency checks.

Reasoning-error detection: logical validation (coherence/structure review) · output testing (run the generated cases/scripts).

Bias detection: review whether generated testware (e.g., synthetic data) is fairly/accurately represented vs the test strategy · check for underrepresented test types (e.g., non-functional).

Exam cue: invented feature not in the brief → hallucination; skewed locale/representation → bias; broken conditional logic → reasoning error. Detection depth depends on the risk level of the task.

3.1.3 (K2) Mitigating hallucinations, reasoning errors & biases

  • Provide complete context in the prompt.
  • Divide prompts into manageable segments (prompt chaining) + verify each step → catch reasoning errors early.
  • Use clear, interpretable data formats (avoid ambiguity).
  • Select the appropriate model for the task.
  • Compare results across models.
  • (Ch 4 adds RAG and fine-tuning as complementary improvements.)

3.1.4 (K1) Mitigating non-deterministic behavior

Full reproducibility isn’t guaranteed, but:

  • Lower the temperature → narrows the probability distribution at inference → more consistent output (but less creative/diverse).
  • Set a random seed → same pseudo-random sequence → improves reproducibility (value high/low is irrelevant).
  • Automate output verification for structured, consistent evaluation.
⚠️ Temperature & seed act at inference. Learning rate is a training setting — a classic distractor.

3.2.1 (K2) Privacy concerns vs. security risks

Privacy concerns:

  • Unintentional data exposure — outputs accidentally reveal sensitive info.
  • Lack of control over data usage — tools store/process data without consent.
  • Compliance risks — e.g., violating GDPR → legal disputes.

Security risks: vulnerable LLM-powered infrastructure (breaches, unauthorized access) · manipulative attacks altering behavior/extracting info · malicious input misleading the LLM.

3.2.2 (K2) Attack vectors — match each to its example

Attack vectorDescriptionExample
Data exfiltrationRequests designed to extract confidential training data.Overlong prompts exceeding the context window → leaks training-data snippets / API keys.
Request manipulationIntroducing data that disrupts output.Doctored images luring the AI into a wrong context → hallucinated criteria / ignored UI defects.
Data poisoningManipulating training data.Injecting fake evaluations / falsified results into the training/fine-tuning set.
Malicious code generationManipulating the LLM to generate backdoors during use.Code that opens a channel to a malicious IP.

3.2.3 (K2) Mitigation strategies

  • Data minimization — process only necessary, non-sensitive data.
  • Anonymization / pseudonymization — mask/replace sensitive data.
  • Secure storage & transmission — encryption + access controls.
  • Resource training — policies for responsible/ethical GenAI use.
  • Systematic human review · compare with another LLM · choose a secure environment (commercial secure offering → secure cloud → in-house for highest control) · regular security audits · stay current with best practices.
Involve senior Security Engineers, Legal, CTO, CISO. GDPR doesn’t ban GenAI but limits lawfulness/purpose of data collection/processing/storage.

3.3.1 (K2) Energy consumption & CO₂

  • Training/running LLMs is compute-intensive; usage raises load on devices, networks, data centers.
  • Image generation ≫ text generation in energy (one image ≈ charging a phone; text ≈ a small %).
  • Energy & CO₂ are typically correlated. GenAI search uses more energy than traditional search.
  • A single text gen seems negligible, but cumulative impact across millions of users is significant.
  • Mitigation: limit unnecessary interactions, right-size the model.
